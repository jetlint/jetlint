## Decisions made along the way

- **Black-box rule implementation**: never read upstream rule source.
  Failures are spec'd from the test fixtures alone.
- **Default-off for the new rules**: the 5 MVP rules keep their
  default-error severity; the 56 additional rules default to off so
  adding them to the binary doesn't silently change project behavior.
- **One commit per rule (when feasible)**: the loop's step 13.
  Some commits batch related quick-wins where each individual rule
  was a small enough change to keep coherent.
- **Stubs with harnesses count as progress**: every rule now has a
  measurable baseline. Without that, "implement the rest" is a black
  box; with it, each rule has a concrete starting number to beat.

## Known gaps

- **no-misused-promises** stuck at 61.4% — the remaining failures
  involve contextual-type checks (variable assignment to void-return
  types, JSX attribute types, object literal property types) that need
  deeper wrapper integration.
- **no-unsafe-member-access** has an implementation but the harness
  shows no improvement over the stub baseline (45.7%) — likely a
  diagnostic-routing or type-detection bug. Documented for follow-up.
- **strict-boolean-expressions** and **no-unsafe-assignment** are MVP
  rules with major surface still unimplemented (45.3% and 39.6%).
  Both have harnesses + scope-notes docs.
- **5 rules below 40%**: prefer-includes, no-misused-spread,
  no-deprecated, prefer-return-this-type, no-unsafe-assignment. Each
  is a wide-surface rule that needs a substantial pass.
